# 独立动作分析模块：视频导入与实时摄像头

日期：2026-10-19

状态：用户已确认产品方案与模型选型。本轮仅编写设计文档，完成后停止，由用户安排 Sol 接手实现。本文不是已实现功能清单。

## 1. 用户需求与设计变更

用户希望看到分析过程，而不是只有完成后的结果；模块应位于底部导航正中间，并同时支持导入视频和摄像头实时识别。已确认导航为：

**训练 · 历史 · 动作分析 · 进步 · 设置**

已确认先做单人、侧面卧推。人体骨架自动识别；用户点选近侧杠铃片中心后自动跟踪。网页也必须实际运行识别，不能只显示 Android 不支持提示或用模拟结果演示。

本文取代旧设计中“仅 Android”“必须关联已完成组”“不支持摄像头”的限制。旧设计的时间戳、缺口传播、二维角度解释和不输出未经验证评分等原则继续适用。旧文档保留为历史记录。

## 2. 目标与非目标

目标：

- 从独立入口直接分析，不以创建训练记录为前置条件。
- 在处理过程中持续看到与实际分析帧对齐的骨架、杠铃点、轨迹和状态。
- 导入模式提供进度、取消、片段选择和完成后复盘；摄像头模式提供预览、开始、停止及本次结果。
- Web 与 Android 共用结果契约与主要交互，分别使用适合平台的解码、摄像头和推理实现。
- 在设备本地处理视频，不上传图像或分析数据。

不纳入本轮：多人与多动作识别、全自动杠铃检测器训练、自动读重量、绝对厘米位移/米每秒速度、动作评分、伤病判断、实时语音教练、云端分析与跨设备同步。

“实时”指持续提供当前画面的识别反馈，不代表预先保证 30/60 FPS。显示实测处理帧率及延迟，不将播放帧率冒充推理帧率。

## 3. 选型与取舍

| 部分 | 决定 | 边界 |
| --- | --- | --- |
| 人体姿态 | MediaPipe Pose Landmarker Lite，单人 | 33 个身体关键点；MediaPipe 不输出杠铃位置 |
| 杠铃跟踪 | OpenCV 金字塔 LK 光流，结合模板匹配校验 | 手动初始化目标区域；不是训练好的杠铃检测模型 |
| 分次与节奏 | 复用并扩展纯 Dart 分析逻辑 | 以有效杠铃轨迹和时间戳计算，不以骨架推测缺失轨迹 |
| Web 推理 | MediaPipe Tasks Vision Web + OpenCV.js/WASM | 隔离耗时工作，不能阻塞 Flutter 页面；不向远程服务器送帧 |
| Android 推理 | 现有 MediaPipe Tasks Vision 与 OpenCV 原生实现 | 增加摄像头输入及增量结果输出 |

选择 Lite 是为了先完成两端可运行的本地方案。若实际侧面卧推骨架质量不足，对同一批视频比较 Full 的质量和耗时后再决定是否增加“精细”档；不把该选项写成首版已承诺功能。

备选的专用目标检测模型需要有许可的标注数据、训练与泛化验证；云端方案增加上传和服务依赖。本轮不选这两条路径。

网页运行库和模型需锁定版本，记录来源、许可证和哈希，优先随站点提供，避免运行时依赖可变 CDN。首次加载需要取得模型资源，本地推理不等于首次访问无需网络。

## 4. 页面与导航

### 4.1 动作分析首页

新增 `/analysis`，处于现有导航外壳内，索引为 2；进步和设置索引顺延。当前及未来 `/analysis/...` 页面须正确高亮该导航项。

首页显示“卧推 · 侧面机位”说明，两个主要入口“导入视频”“实时拍摄”，以及本地已保存的分析项目。没有训练组也可以开始和保存。拍摄说明强调固定机位、近侧杠铃片和上半身可见、全程不出画、不变焦。

现有“本场已记”和历史详情里的复盘入口保留。旧 `/review/:setId` 路由兼容已有入口，导向相应分析项目；从组进入时预填组关联，从独立入口进入则默认无关联。

### 4.2 共用分析画面

主区域是实际视频画面，叠加骨架连线、杠铃中心、局部跟踪区域及累计轨迹；提供骨架/轨迹开关。画面下方显示人体与杠铃各自状态、当前阶段、完整次数、处理状态。导入时额外显示进度，摄像头时显示时长和处理帧率。

骨架点、连接线只显示达到有效性条件的部分。杠铃丢失时断开轨迹并提示“重新标记杠铃”；姿态失败与杠铃失败互不阻断。下降/推起用颜色和文字区分，不能只依赖颜色。

人体识别可以先启动。杠铃未标记时提示点选，不输出基于杠铃的次数和节奏。实时次数属于暂定结果，停止后再完成边界计算并允许修正。

## 5. 导入视频流程

1. 选择本地视频，读取时长、尺寸与旋转，显示真实预览。选取一组片段，首版沿用最长 3 分钟分析范围。
2. 在片段首个可用帧点选近侧杠铃片中心，调整区域大小；保留原视频，不改变相册文件。
3. 开始后由分析时间轴驱动画面。每次显示已处理帧及同时间戳识别结果，不把未来画面配上旧骨架。速度不足时分析画面可以慢于正常播放。
4. 按时间戳处理、分批输出增量观察结果；进度反映已处理的片段时间，不使用计时器制造进度。
5. 取消立即停止调度并释放资源；可以保留已得到的部分结果，但标记“不完整”，不能标作已完成。已保存的旧结果不被失败或取消覆盖。
6. 完成后提供正常播放、慢放、前后逐帧、次数跳转、人工重新标记和分次边界修正。
7. 用户保存独立项目，可选择关联已有完成组。视觉次数和训练记录次数分别显示，不自动改写训练记录。

## 6. 实时摄像头流程

1. 点击“实时拍摄”后才请求摄像头权限；默认后置摄像头，支持可用设备切换。不请求麦克风，录像不包含音频。
2. 显示实时预览及骨架，让用户调整机位。点选当前画面中的杠铃片中心，标记绑定对应帧时间，跟踪从该帧初始化。
3. 点击“开始”后记录本次观察序列及视频，持续显示识别结果。未标记杠铃仍可观察骨架，但必须明确缺少杠铃分析。
4. 采用有界队列。处理跟不上时丢弃过期输入，不积压成越来越延迟的“实时”画面；记录真实时间间隔。时间间隔超出跟踪允许范围时转为丢失，不强行连续跟踪。
5. 叠加层和画面使用同一呈现帧；若原始预览继续播放，超时的检测结果必须隐藏，不能把旧骨架贴在新动作上。后台处理与界面绘制独立。
6. 点击停止或达到 3 分钟上限后停止录像与推理，进入本次结果，可回放和保存。完整次数在停止后确认；最后半次不计为完整次数。
7. 摄像头切换、前后镜像切换或分辨率变化导致坐标系变化时，清空当前跟踪状态并要求重新标记，不沿用旧坐标。
8. 离开活动分析页需处理未保存结果，停止摄像头及推理。后台暂停/锁屏后终止本段，保留可恢复的部分结果并明确中断，不自动静默恢复录像。

Web 必须检查安全上下文与媒体能力：本机 localhost 可用于开发，手机访问电脑的普通 HTTP 局域网地址不能作为摄像头可用的保证。正式部署使用 HTTPS。权限拒绝、无摄像头、设备占用时给出对应说明，并保留导入入口。

浏览器录像格式通过能力检测选择，不硬编码只接受 MP4。若录像能力缺失但摄像头推理可用，开始前明确标注“仅实时预览，无法保存视频复盘”；允许预览，不声称能提供停止后的完整视频回放。

## 7. 时间、坐标与有效性

- 所有观察结果携带源帧时间戳；摄像头使用同一单调时钟并建立录像时间映射。分次不用帧序号除以假定帧率。
- 结果记录旋转校正后的尺寸、归一化坐标、镜像显示变换和质量状态。计算角度时恢复等比例图像坐标，避免宽高分别归一化扭曲角度。
- 跟踪目标是选定杠铃片中心的二维投影，不是杠铃重心，更不能用手腕坐标代替。
- LK 前后向误差、局部运动一致性与模板相似度共同校验。模板只在有效状态下更新，不在跟踪失败后从背景重建模板；阈值版本化并经实测调整。
- 重新标记建立新轨迹段。缺口不连线、不跨缺口平滑、不补造点；依赖缺口的指标显示未知，其他有效片段可继续使用。
- 次数统计只纳入完整下降—推起周期，排除出杠、回架、半次；暂停时间不是触胸或比赛停顿判定。
- 节奏、相对幅度和二维肘角沿用旧设计定义；相对幅度只适用于同组固定机位。机位移动的样本不得用于宣称精度达标。

## 8. 架构与数据契约

避免继续把平台调用、任务循环和所有 UI 塞进现有 `VideoReviewPage`。保留 Flutter 的 features / state / domain / data 分层，分离以下职责：

| 单元 | 职责 |
| --- | --- |
| 分析首页和会话页面 | 模式选择、标记、状态展示、回放、保存与关联 |
| 分析会话控制器 | 状态机、取消、帧调度、资源所有权、增量结果聚合 |
| 平台媒体适配器 | 导入解码、摄像头、录像、帧时间轴及本地媒体引用 |
| 平台视觉适配器 | MediaPipe 姿态与 OpenCV 跟踪，输出统一观察结果 |
| Dart 领域分析 | 分次、节奏、质量传播与人工修正 |
| 项目存储 | 项目元数据、媒体、结果、版本、迁移和文件清理 |

一次观察包含：会话 ID、帧时间戳、图像尺寸、姿态关键点/可见性、杠铃位置或缺失原因、轨迹段 ID、处理耗时。增量事件另含阶段、已处理时间及可恢复错误。回调携带会话代次，已取消会话的迟到结果不得写入新会话。

Web 使用 Worker 承载可移出的推理与跟踪，验证目标浏览器的帧传输和 GPU/CPU 路径。不能因 Worker/GPU 初始化失败直接退回长时间阻塞 UI 的循环；应使用经过验证的降级路径或明确能力错误。Android 使用后台执行器和批量观察事件，不逐帧通过平台通道搬运完整像素。

状态：加载模型 → 准备输入 → 预览/标记 → 分析中 → 已停止/已完成/已取消/失败 → 复盘 → 已保存。无杠铃锚点和跟踪丢失是单独的识别状态，不把整个会话一律判为失败。

## 9. 存储、迁移与兼容

现有 schema 9 的 `video_review` 以 `set_id` 为主键，不能直接承载独立项目。新增后续迁移，引入独立项目 ID；每项包含可空组 ID、输入模式、媒体引用、时间范围、结果版本、模型/算法版本、完成状态与创建更新时间。

- 一项最多关联一个完成组；保持每组最多一个当前分析项目。换绑冲突时明确提示，不能静默覆盖。
- 迁移旧行保留媒体目录、结果内容和原组关联。迁移与清理协同：旧清理器不得因只查询旧表而删除新项目媒体。
- 删除训练组时保留独立分析项目并解除关联；这替代旧的随组级联删除策略。删除分析项目只删除受管理副本，不删除用户原媒体。
- Android 使用应用私有且不参与系统云备份的媒体目录；Web 使用浏览器本地 Blob 存储和元数据存储，不把对象 URL 当作持久媒体地址。
- Web 保存前检查配额并处理写入失败；提示浏览器清理站点数据可能删除本地分析。临时 URL 在结束使用时释放。
- 采用写临时结果后切换引用的保存方式。重算失败保留旧结果；未保存会话不承诺跨进程断点续跑。
- 现有训练 JSON 备份继续不包含视频和视觉结果，不能导出本地私有路径。恢复训练备份时保留独立分析项目、解除原有组关联，并在恢复确认中说明；事务失败维持原数据和关联。

上述持久化细节是为独立入口补齐的工程设计决定，Sol 应据此实现并验证，不误用旧组级联清理行为。

## 10. 验收要求

### 产品与浏览器

- 360px 宽度及桌面下五项导航均可操作，动作分析确实在正中间；无训练记录也可进入两种模式。
- Web 导入真实视频时显示真实帧、骨架和已初始化的杠铃跟踪；分析结束前可看到增量变化，取消及时响应。
- 摄像头真实运行：权限、切换、镜像、开始/停止、退出释放与录像回放可验证。没有设备时标注未验收，不以模拟流替代结论。
- 在慢设备上输入队列不无限增长，界面能响应；记录处理 FPS、延迟与丢帧情况，不预设性能已达标。

### 识别与数据

- 至少 3 段固定侧面、清晰全程视频及 2 段遮挡/出画/机位变化样本，记录来源、使用条件、人工次数、抽检位置和失败区间。
- 对清晰样本沿用旧设计的工程目标：位置误差中位数不超过可见近侧杠铃片直径的 5%；时间边界误差不超过 0.2 秒或两倍采样间隔中的较大值。这是验收目标，绝非已经达到的性能。
- 骨架额外记录肩/肘/腕有效输出比例和明显错侧/跳点，比较 Lite 与 Full 时使用同一批样本；不能只凭骨架“画出来了”就宣称正确。
- 丢失跟踪、未标记、模型失败和半次动作的状态真实；不通过人体点或静止背景点伪装杠铃跟踪成功。
- 测试真实时间戳、坐标变换、缺口传播、取消后迟到回调、旧数据迁移、独立保存、删除组解关联、备份恢复及失败回滚。
- 回归原训练、历史和进步功能；完成 Flutter 静态检查、相关自动测试与两端构建。真实视频/摄像头验证与这些检查分别报告。

1. 接手后阅读本文与代码，编写实现计划；不要直接复用旧 Android-only 计划作为新任务范围。

5. Android 增量过程展示和摄像头，统一两端结果与状态。
6. 执行真实样本、设备验证与回归，按已完成/未验证如实报告。
