# 多动作与多机位分析模块设计

日期：2026-10-19

状态：产品方向已由用户讨论确认，待用户审阅本文；本文定义后续设计与实现的产品边界，不表示所有能力已经实现或验证。

本文扩展 `2026-10-19-motion-analysis-design.md` 中以侧面卧推为中心的产品范围。既有文档描述的本地处理、时间戳、取消隔离、媒体保存、旧项目兼容及不伪造缺失数据等基础原则继续有效；若与本文的动作范围冲突，以本文为准。当前实现与验证状态见 `2026-10-19-motion-analysis-execution.md`，不得将本文的目标误读为已经完成的功能。

## 1. 产品目标

将“动作分析”发展为一个支持动作查找、视频分析和结果复盘的独立模块。用户可在动作库中查找动作，选择动作后直接进入对应分析；也可从导入视频或实时拍摄入口开始，再选择动作。

首批支持以下基础版本：

- 杠铃深蹲
- 杠铃卧推
- 杠铃硬拉
- 自重引体向上

每个首批动作都以提供以下分析为产品目标：

1. **次数**：识别完整重复，不把准备、回架、半次或不确定片段计为完成次数。
2. **动作轨迹**：展示可观测身体关键点轨迹；杠铃动作还展示经验证的杠铃轨迹。轨迹保留缺失区间，不跨缺口插值成虚假的连续路径。
3. **动作质量提示**：按动作定义可解释的观察项、触发条件和证据范围。提示是视频分析反馈，不是医疗意见或绝对技术判决；证据不足时显示无法判断。

支持从正面、侧面、斜侧面等机位分别分析。用户可以只分析一个角度，也可将同一个训练动作的多个角度加入同一分析项目，分别查看或综合对照。

## 2. 非目标与准确性边界

- 不承诺任意拍摄方向、遮挡和画质下均能给出所有指标；“尽可能多角度可分析”不等于单摄像头不存在视线遮挡。
- 不把不同时间拍摄的片段拼成同步三维测量；多角度综合报告汇总互补观察，不伪称多视角几何重建。
- 不在数据不足时强行给出姿势质量结论，不输出伤病诊断、医疗建议、评分或未经验证的绝对距离/速度。
- 首批基础动作不自动意味着其全部握法、站距、器械或动作变式都受支持。变式作为独立目录条目和能力配置逐步加入。
- 动作库内容不以第三方会员视频、图片或说明的批量提取为前提；仅使用拥有相应使用权的媒体和数据。

## 3. 信息架构与用户流程

### 3.1 动作分析首页

动作分析位于主导航中。首页包括：

- 动作库入口及搜索。
- 按器械、身体部位、动作类别筛选。
- “导入视频”和“实时拍摄”快捷入口。
- 最近的独立分析项目及历史项目。

### 3.2 动作库与动作详情

动作库是动作分析模块内的可单独浏览页面，不新增主导航项。动作卡片展示动作名称、器械/自重类型、主要部位和可用状态。目录可包含尚未开放自动分析的动作，但必须区分“可分析”“目录信息”“尚未验证”等状态。

动作详情显示动作说明、合法使用的示意图或视频、建议机位、拍摄质量要求、当前可用的次数/轨迹/质量提示，以及各机位限制。详情页的主要操作是“导入视频分析”和“实时拍摄分析”。选择动作后，分析会话携带动作 ID、版本和机位配置，不再默认进入卧推规则。

### 3.3 分析会话

会话流程为：选择/确认动作 → 选择导入或摄像头 → 选择或识别机位 → 预览和质量检查 → 分析 → 复盘与保存。独立入口可以先选媒体，再补选动作。

机位由用户显式选择；系统可提供机位提示或建议，但在验证完成前不静默改变用户选择。若关键关节或器械可见度不满足某指标要求，界面说明具体缺失证据，并暂停该项结论；其他有效指标可继续输出。

### 3.4 多角度项目

项目可以包含一段或多段观察片段。每段片段有自己的媒体引用、时间轴、机位、分析结果和质量状态。用户可：

- 单独打开某个机位，查看该角度的骨架、器械轨迹、次数和提示。
- 在综合视图中按对应次数/片段并排或切换比较多个角度。
- 将另一段视频加入现有项目，或将独立项目关联到同一训练组时按规则合并/提示冲突。

综合报告仅汇总可对应的结果与证据。不同视频无法可靠匹配次数时，分角度列示，不自动认为第 N 次必然是同一次动作。不同角度结论冲突时显示冲突与来源，保留各角度判断，不通过简单平均隐藏差异。多角度同步三维融合属于未来单独设计，不在本方案承诺范围内。

## 4. 动作与机位能力模型

动作库数据与分析算法分离。新增动作应通过配置/领域实现注册，不应复制首页、页面流程、存储流程或整套平台桥接代码。

每个动作定义稳定的动作 ID 和版本化分析档案，至少包含：

- 名称、器械类型、身体部位、类别、变式关系、展示资源及其授权来源。
- 有效重复周期的开始/结束事件及排除规则。
- 所需人体关键点、可选器械目标、关键点有效性阈值。
- 可用机位列表及每个机位支持的指标、遮挡限制和拍摄提示。
- 质量提示定义：名称、触发逻辑、所需证据、置信状态、解释文案和版本。
- 分析器 ID/版本、模型依赖和结果兼容版本。

数据层支持目录条目与分析能力分开发布。这样可以先丰富目录，再逐个动作/机位开放通过验证的分析能力。动作、机位和指标之间使用数据驱动的能力描述，避免散落的 `if exercise == ...` UI 判断；有独特逻辑时由明确的动作分析器实现。

## 5. 首批动作的分析定义

下列为首批分析目标，具体阈值和机位支持矩阵须经样本标注和验证后确定；在验证前不可宣称准确率达标。

| 动作 | 次数事件 | 轨迹目标 | 候选质量观察 | 机位关注点 |
| --- | --- | --- | --- | --- |
| 杠铃深蹲 | 站立 → 下蹲 → 返回站立的完整周期 | 髋、膝、踝、躯干关键点；可见杠铃时记录其轨迹 | 下蹲幅度、躯干姿态变化、重复间一致性 | 侧面观察深度与躯干；正面观察左右差异与膝部运动；斜侧面用于补充但考虑透视 |
| 杠铃卧推 | 杠铃下降 → 推起完成的完整周期 | 肩、肘、腕以及被可靠跟踪的近侧杠铃片中心 | 动作幅度、杠铃路径和重复间一致性 | 侧面观察杠铃路径与肘部变化；正面/斜侧面补充左右差异，受遮挡与透视限制 |
| 杠铃硬拉 | 杠铃离地 → 站直 → 杠铃回到起始位置的完整周期 | 髋、膝、踝、肩、腕与杠铃目标 | 躯干姿态变化、杠铃相对身体路径、重复间一致性 | 侧面观察前后路径与髋/躯干变化；正面补充左右偏移和对称性 |
| 自重引体向上 | 悬垂 → 上拉达到定义顶点 → 返回底部的完整周期 | 肩、肘、腕、髋及头/躯干垂直轨迹 | 动作幅度、身体摆动、重复间一致性 | 正面/斜侧面观察左右与躯干摆动；侧面观察身体摆动与动作幅度 |

“膝盖内扣”“左右不对称”等提示只在相应机位、可见度和校准条件已验证时启用。不能从单一侧面画面推断正面不可见的细节。质量提示采用观察性措辞，例如“本段膝部轨迹向内变化”，并显示机位/可见度依据，不直接给“错误”或伤害结论。

## 6. 视觉与分析架构

维持平台适配与领域分析分层：

- **人体姿态适配器**：MediaPipe Pose 输出带时间戳、可见度和坐标元数据的人体关键点。它提供姿态输入，不直接负责分类所有动作或评定动作质量。
- **动作识别器**：基于关键点时间序列和动作档案识别候选动作/重复阶段。入口已选动作时可做该动作的分段与状态识别；通用自动动作识别作为后续能力，未知动作不得误分类为首批动作。
- **器械检测与跟踪适配器**：检测和跟踪杠铃/哑铃等目标，输出目标类别、位置、置信度和轨迹段。检测器可共享，跟踪器在目标稳定时降低重复全帧检测频率；丢失时明确断段并重新检测/要求重标记。人体关键点不得替代器械位置。
- **动作分析器**：根据动作 ID、机位和已验证档案计算次数、轨迹特征与质量观察。动作专属逻辑通过稳定接口接入。
- **会话控制器**：负责状态、时间戳、帧调度、取消代次、多媒体片段、结果增量和资源释放。
- **项目存储与报告**：一个项目可包含多个片段，每段独立存储；综合报告引用而不破坏原始片段结果。

人体姿态模型与器械模型是否合并，不预先设定为单一大模型。先比较共享预训练模型加轻量目标检测/跟踪与联合模型的准确度、延迟、功耗、模型大小和跨端可用性；以实测收益决定。视频默认本地处理，除非未来另行明确改变隐私设计并征得用户同意。

## 7. 结果契约与质量表达

所有观察结果包含项目/片段 ID、动作档案版本、源帧时间戳、机位、图像尺寸及方向、坐标变换、姿态关键点及可见度、器械观测或缺失原因、轨迹段 ID、处理耗时和输入质量状态。

次数对象包含起止时间、阶段边界、完整性和置信状态。质量提示对象包含指标 ID、观察值或类别、置信/证据状态、关联时间段、所需可见关键点、动作/机位配置版本及面向用户的解释。缺失数据产生“未知/不可评估”，不自动按通过或失败处理。

项目级汇总须保留来源片段及机位；可让用户按角度比较同类指标，但不把不可比坐标系中的绝对轨迹直接叠成同一物理空间。归一化轨迹仅明确标为归一化或相对参考，不称为厘米或米每秒。

## 8. 数据采集、训练与验证

- 动作卡片和动作示意媒体与模型训练数据分开管理。会员动作库的目录信息不能自动作为训练数据许可。
- 每个动作/机位准备获得授权且多样化的视频样本，按用户、视频、动作阶段标注；训练、调参和验收应按人/视频隔离，避免同一段内容泄漏到多份数据集。
- 标注完整重复边界、关键动作阶段、关键点/器械可见性、失败区间、机位、遮挡、机位移动及质量提示所需判断。质量提示需要明确的人工标注准则和争议处理方法。
- 每个动作/机位独立报告计数误差、边界误差、轨迹误差、质量提示精确率/召回率、不可评估比例、处理 FPS/延迟及设备条件。综合多机位结果另评估次数匹配准确度和结论冲突率。
- 首批动作/机位未达到预先定义的验收目标时，保持“实验/部分支持”状态，并禁用未达标提示；不能通过扩大目录数量替代准确性验证。

## 9. 本地媒体、备份与兼容

继续沿用已有独立分析项目存储方案，并扩展为项目包含多个观察片段的结构。训练组关联仍可为空；独立项目不以已完成训练组为前提。保留旧 `/review/:setId` 入口与现存卧推项目兼容，迁移不得丢失旧视频、分析结果、机位信息或训练组关系。

删除训练组时，保留分析项目并解除关联。训练 JSON 备份不包含视频、关键点或视觉结果。多角度新增视频采用应用管理的本地副本和引用清理规则；删除/替换一个片段不得误删同项目其他片段或用户原始媒体。保存新分析结果后才更新对应引用，失败时保留旧结果。

## 10. 分阶段交付

1. **领域扩展**：动作目录、动作档案与机位能力契约；用现有卧推回归证明旧入口和结果兼容。
2. **首批动作分析**：依序实现杠铃深蹲、杠铃卧推、杠铃硬拉、自重引体向上的单片段计数、轨迹、已验证质量提示，并明确支持的机位。
3. **多角度项目**：多个片段同项目管理、独立回放和报告对照；实现次数匹配与冲突呈现。
4. **器械检测提升**：建立授权标注集，比较专用检测模型、跟踪方案及资源消耗，按收益扩展杠铃/哑铃目标类型。
5. **后续动作扩充**：根据动作库优先级新增档案、样本、分析器和机位验收，不改动通用项目流程。

每一阶段分别报告软件自动化检查、真实视频评估和真实设备/机位评估。构建成功不得代替动作识别准确度验收。

## 11. 设计验收问题

- 主导航仅有一个动作分析入口；动作库在模块内独立浏览，支持搜索和器械/部位筛选。
- 用户能从目录选动作直接开始分析，也能从媒体入口补选动作。
- 首批四个基础动作在动作档案层可独立定义动作周期、机位、轨迹目标和质量提示。
- 任一新增动作不需要复制整套页面、媒体桥接、项目存储和通用报告流程。
- 每段视频保留机位及独立结果；单角度报告与多片段综合视图都可用。
- 每项质量提示都可追溯到时间段、关键点/器械证据、动作定义和机位限制；信息不足时明确不可评估。
- 多角度比较不伪造同步三维结果；动作数无法匹配时保留分角度结果。
- 器械检测与跟踪不得以人体关键点代替，模型选型须以准确度和端侧性能实测作决定。

## 12. 给后续实现的说明

实现前应先针对本文写实现计划，并核对当前未提交工作区中已有动作分析代码、数据库迁移和验证证据。本文是产品和扩展边界；既有实现记录是当前状态，两者不得混淆。首个实现任务优先落地动作档案/能力接口与单动作兼容，然后逐项扩展四个首批动作和多角度项目。不要把“后续可扩展”处理成首版支持任意动作，也不要把候选质量观察写成已达标功能。
