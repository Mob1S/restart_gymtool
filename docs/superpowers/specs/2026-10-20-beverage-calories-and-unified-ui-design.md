# 饮料热量管理与全局 UI 统一设计

日期：2026-10-20

状态：功能与 UI 方向已在对话中确认，本文待用户审阅。本文描述目标，不代表功能、公共数据覆盖或识别效果已经实现、验证。

## 1. 目标与范围

新增独立「热量」板块，记录喝了什么、喝了多少以及据此计算的饮料热量。优先服务可乐等常见包装饮料，同时支持现制饮品的自定义配置。以常喝饮料库减少重复输入。

首版包含：

- 个人饮料库与在线公共饮料搜索。
- 搜索、拍照或导入图片辅助识别、手动输入三种建档方式。
- 每日饮用记录，以及近 7 天／30 天趋势和饮料热量贡献。
- 修改、删除、补记，离线记录，本地存储和 JSON 备份恢复。
- 全 App 统一视觉与交互组件，调整底部导航。

首版不做食物热量重点管理、饮料热量预算、全天热量目标、运动消耗抵扣、跨次或跨天的整瓶余量追踪。没有承诺全品牌现制饮品目录、自动推算糖度和加料热量，也不增加账号、云同步或付费服务作为前提。

## 2. 信息架构与全局 UI

底部导航固定为：**训练／热量／动作分析／历史／进步**。动作分析保持居中。历史和进步继续服务训练；饮料趋势归属热量板块。

设置移到五个主页面右上角的统一入口；设置页保留独立返回行为，回到进入它的页面，不错误高亮某个底部标签。训练记录、详情、分析会话等任务页面保留合理的返回与退出保护，不强行套入首页布局。

全局统一范围覆盖训练、计划、记录、历史、进步、动作分析、设置和热量页面：

- 延续橙色品牌与深浅主题，共用颜色语义、字号、间距、圆角、图标和数值排版规范。
- 标题、日期切换、主要操作和辅助入口有一致层级；每页突出一个主要任务。
- 统一按钮、列表行、卡片、数值输入外观、底部弹层、日期选择、错误、加载、保存反馈和空状态。
- 数值与单位紧邻；重量、次数和饮用量保持各自合理的操作方式，不为外观一致破坏训练效率。
- 点击立即反馈；页面和弹层过渡短而自然，可中断；连续调整数值不等待动画；尊重减少动态效果设置。
- 保持触控区域、对比度和键盘可操作性。适配小屏、横屏、大字体、安全区及键盘遮挡；手势操作保留可见替代入口。

以现有 `lib/ui` 组件、主题和 tokens 为统一入口；先完善共用组件，再迁移页面，避免各页面独立添加一套样式。不会把网页参考中的 CSS 或 React 实现直接移植到 Flutter。

## 3. 热量页面与记录流程

### 3.1 首页

按「日期与今日合计 → 常喝／最近入口 → 当天明细」排列，提供趋势入口和固定可达的「记录饮料」按钮。

合计文案为「已记录饮料热量」，不表示全天摄入。含估算记录时提示「含估算」；含未知热量时提示未计入条目数量。空列表显示「尚未记录」，不得表示当天实际摄入为零。

### 3.2 常喝饮料

选择饮料 → 确认饮用量及时间 → 保存。默认一瓶／一杯，可选半份、多份或输入 mL。只有已知对应份量体积时才支持份数与 mL 换算；不把现制杯型的名称当作准确体积。

保存按钮防重复提交。成功后更新当日记录与合计，并提供撤销本次新增的入口；写入失败保留输入。修改、删除和补记均触发汇总与趋势刷新。

个人库支持收藏／取消收藏、编辑及归档。归档不删除历史记录；同名但版本或规格不同的饮料可并存。

### 3.3 添加饮料

三种方式进入同一个核对表单，核对后保存到个人库并继续本次记录：

1. 搜索：先显示个人库，再显示公共结果；标明品牌、版本、规格、热量基准与来源。公共结果不会仅因名称相同覆盖个人资料。
2. 拍照／导入图片：提取图片中已有的名称、能量、单位、计量基准和容量，显示原图供核对；缺失或不确定字段要求补全。识别不自动提交。
3. 手动：录入名称、品牌、规格、热量与来源，可保存没有热量的条目为「待补热量」。

包装饮料区分普通、无糖等版本及容量。现制饮品保存品牌、品名、杯型、糖度、加料和可选冷热信息；配置不同不默认沿用旧热量。

## 4. 热量计算与可信度

「精准」定义为来源明确、规格匹配和计算正确，不承诺标签本身没有误差。

- 支持 kcal 与 kJ，按 `kcal = kJ / 4.184` 换算。
- 支持每 100 mL、每瓶／杯／份；每份对应体积可留空。
- 按每 100 mL 标注时，热量为标准 kcal × 实际 mL / 100。
- 按每份标注时，热量为标准每份 kcal × 实际份数。
- 不凭空将每 100 g 当作每 100 mL；此类输入必须选择可验证的份量依据或由用户补充，不默认饮料密度为 1。
- 保留原始标注值、单位、基准以及未按显示位数取整的计算结果。使用十进制计算；汇总后再四舍五入为一位小数，去掉末尾 `.0`。正数不足 0.1 kcal 时显示「<0.1」，不显示成零。
- 热量允许明确的零，未知值使用空值；饮用量必须为有限正数。禁止负值、非有限数和缺少计算基准却生成数值。
- 不把三分糖等价成全杯热量的 30%，不凭照片外观猜热量。

来源和核对状态分别保存。来源区分包装标签、品牌官方、公共数据库、个人估算；识别是录入方式，不是可信度来源。公共条目经用户确认也不自动变成官方数据。

同款存在冲突时优先采用用户核对的实际包装资料，保留来源说明。饮料库更新不会重算历史：每条记录保存当时的名称、规格、热量依据、来源、数量和计算快照。若要修正旧记录，需要编辑对应记录。

## 5. 公共搜索与图片识别边界

包装饮料公共搜索首选评估 Open Food Facts，通过独立适配器接入。其营养数据含社区贡献，不承诺中国商品覆盖或数据无误。正式接入前验证真实可乐样本、中文搜索可用性、规格区分、营养字段、服务访问及使用要求；不能以硬编码假结果作为搜索完成。

现制饮品只有取得可核实、可使用的对应官方资料时才提供数值条目。首版不以搭建全面现制目录为完成条件；自定义和图片录入支持现制饮品。未匹配的规格不能静默套用相近条目。

网络失败、超时、无结果分别给出明确状态；个人库始终可用，并保留手动及图片入口。取消或更换查询后，旧请求结果不能覆盖新查询。采用节流／防抖及适当缓存，避免每次键入都请求公共服务。

图片识别目标覆盖 Android 与 Web 的图片输入：Android 支持拍照和选图，Web 支持选图、设备支持时可拍照。使用设备端识别，不默认上传原图或引入用户付费 API；结构化解析必须识别能量单位和基准。实现计划先验证所选本地识别方案对中文营养标签、反光、旋转和小字样本的效果与性能。无法满足时明确报告限制，不把手动输入按钮当作识别功能已交付。

原图仅作为本次核对材料，默认不长期保存；持久化保留结构化来源、可选来源 URL 和核对时间。取消操作清理临时资源。

## 6. 趋势

提供截至所选日期的近 7 天／30 天记录热量图、区间总计和按饮料汇总的贡献列表。图表与当天明细使用同一计算口径。

有明确零热量记录的日期可显示 0；没有记录的日期显示缺口／未记录，不当作零。仅有待补热量条目时显示「热量待补」；有部分已知值时显示已知合计和不完整标识。区间总计不推断遗漏摄入，饮料贡献排行只使用已知热量并标明估算或缺失情况。

日期沿用现有本地自然日工具。记录保存发生时间及记录所属的本地日期，修改时间时同步更新所属日期；补记默认落到用户选择日期。跨午夜、重启和查看历史不能把记录误分到其他日期。

## 7. 架构与持久化

沿用 Flutter、现有状态管理与 SQLite repository 分层：

- 领域层：饮料规格、来源、份量、能量换算、记录快照及趋势计算；不依赖 UI、网络或 OCR。
- 数据层：个人饮料库、饮用记录 repository；公共搜索适配器；平台图片识别适配器。
- 状态层：搜索与识别草稿、提交状态、日期和趋势加载；沿用数据 revision 刷新机制。
- UI 层：热量首页、添加／核对表单、份量确认、个人库管理和趋势页面；复用全局组件。

饮料库实体含 ID、名称、类型、品牌、配置、容量、热量基准、来源与核对信息、收藏／归档状态及时间。记录实体含 ID、可选饮料库引用、发生时间、所属日期、饮用量及完整快照。

饮料资料和记录分离；归档或删除库条目不级联删除饮用记录。迁移基于实施时实际数据库最高版本递增，不假定旧设计文档中的版本仍是最新。当前工作区已有动作分析相关改动，实施时保留并兼容，不覆盖或混入不相关修改。

## 8. 备份与兼容

新增备份版本，包含个人饮料库、饮用记录及其快照与来源字段；不包含临时识别图片、公共搜索缓存。

恢复新版本备份时：

- 预览明确列出训练、饮料库和饮用记录数量及替换范围。
- 饮料与原有受恢复管理的数据使用一次事务，验证失败不写入，写入失败整体回滚。
- 完整保留待补热量、零值、原始单位、归档状态、日期及历史快照。
- 恢复后统一刷新各页面，不显示旧缓存。

恢复旧版、不含饮料数据的备份时，保留本机饮料库和饮用记录，并在预览中明确说明。新版本中饮料数组明确为空时才表示恢复为空，不能将缺失字段静默当空数组；新版本缺少必需字段按损坏文件拒绝。

继续遵循现有容量限制，新增条目计入记录总数。旧版应用不保证读取新增备份版本。现有动作分析项目和视频的备份／恢复边界不因本功能扩大。

## 9. 验证与交付标准

- 计算：kJ／kcal、不同基准、半份与多份、mL、精度与汇总、显式零、未知值及非法值。
- 历史：编辑库条目不改历史，修改／删除记录后汇总一致，跨日与补记分组正确。
- 数据：旧库迁移保留训练与分析内容；新备份往返；旧备份保留饮料数据；恢复失败回滚。
- 搜索：真实包装饮料样本、名称与规格匹配、无结果、断网、超时、取消及过期响应隔离。
- OCR：实际标签和截图能进入核对表单，单位／基准缺失不生成虚假热量，取消不保存。
- UI：五个导航入口、设置返回路径、所有主功能的统一组件及深浅主题；小屏、大字体、键盘、减少动态效果。
- 回归：训练记录与恢复、计划、历史、进步和动作分析核心流程仍可操作。

验收记录区分自动测试、Web 实际操作与 Android 真机验证；构建成功不代表相机、识别和网络数据覆盖已验收。
