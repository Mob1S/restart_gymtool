# 卧推侧面视频复盘设计

日期：2026-10-18  
状态：首版范围已获确认；2026-10-19 用户要求继续开发，并明确暂时没有真实视频、先继续开发。真实视频和真机准确性仍待验收。

## 1. 目标与已确认范围

在现有 Flutter 健身记录工具中增加训练后复盘：用户从一条已完成组记录添加固定侧面拍摄的卧推视频，查看杠铃轨迹、每次动作的节奏和组内一致性，并用人体骨架辅助观察。

用户依次选择了：训练后视频复盘、卧推、固定侧面拍摄，并确认了单组分析、手动选定近侧杠铃片、可修正分次、视频慢放与逐帧查看、本地保存和关联训练组的首版范围。

首版以 Android 为交付平台。Web 保持现有训练记录功能；复盘入口明确显示该平台暂不支持本地视频分析，不用演示数据伪装分析完成。

首版不包含实时训练提醒、云端上传、其他动作、自动识别杠铃重量、动作综合评分、医学诊断、绝对位移或绝对杠速、跨训练日期并排比较。跨日期比较是未来扩展，不列为本轮验收项。

## 2. 方案选择

| 方案 | 优点 | 取舍 |
| --- | --- | --- |
| **采用：本地视频复盘，手动初始化杠铃追踪，姿态识别辅助** | 与训练后查看习惯一致；无需上传视频；追踪失败可回看、修正 | 需要视频解码、追踪与姿态模型的真机验证 |
| 实时摄像头分析 | 拍摄时即可显示结果 | 不符合本轮优先场景，持续性能与交互要求更高 |
| 云端视频分析 | 可使用更大的模型 | 引入网络、上传与服务维护成本 |

人体识别与杠铃追踪分开：人体模型不输出杠铃位置，不能把手腕位置当作杠铃中心。姿态识别失败不得阻断可靠的杠铃轨迹和节奏分析。

## 3. 入口与操作流程

### 3.1 入口

- 在「本场已记」和历史训练详情的已完成组操作中增加「视频复盘」。训练尚未结束也能为已完成组添加视频。
- 首版每组保留一个复盘项目；再次进入打开既有项目。替换视频前明确提示将替换该组的复盘内容。
- 分析入口标明「卧推 · 固定侧面」。允许用户将自建卧推动作关联进来，不依赖动作中文名称的模糊匹配。
- 只有已完成组可创建复盘。首版不创建未关联组的独立视频库。

### 3.2 操作步骤

1. 选择本地视频，将其复制到应用私有目录，避免依赖随时失效的临时文件授权。
2. 显示视频预览与侧面拍摄说明，用户选取一组的起止时间。裁剪采用时间范围，首版不要求重编码导出。
3. 用户在选定片段的首个可用画面点击近侧杠铃片中心；显示可调整的追踪区域，避免把人体或背景选入。
4. 开始分析，显示阶段与实际进度，提供取消。处理串行执行，避免多个视频同时占满内存。
5. 打开复盘页；可修正追踪位置、次数边界及底部停顿边界，修正后重新计算受影响结果。
6. 保存到当前组。退出未保存的编辑时提示保留已有结果或放弃本次编辑。

拍摄说明：手机固定，尽量正对身体侧面，画面覆盖近侧杠铃片及上半身，完整下降和推起时杠铃片不出画；整组不移动手机或变焦。机位是否合格不能只靠模型自动保证。

## 4. 复盘页面

### 4.1 视频区

- 视频保持正确旋转方向与比例，提供播放、暂停、0.25× / 0.5× / 1×、前后逐帧。
- 杠铃轨迹和人体骨架各有独立开关，下降与推起使用不同颜色并有图例。
- 视频、轨迹、骨架和选中次数共用原视频时间轴。留黑边、缩放或旋转后，点击标记与叠加坐标仍一致。
- 丢失追踪的区间不连线，低可信骨架点及相邻连线隐藏。显示「此片段识别不清，可重新定位」。

### 4.2 次数条

- 每次用独立区块标示下降、底部停顿和推起，点击跳到该次起点。
- 支持增删一次、修正起止、修正底部边界；禁止重叠、倒序或超出裁剪范围。
- 只统计完整的下降—推起周期。出杠、回架及片段边缘的半次可以回放，但不纳入完整次数统计。
- 自动识别次数与原训练记录次数分别显示；差异不自动改写记录。

### 4.3 对比区

- 每次下降、底部停顿和推起的时间。
- 每次画面内的相对垂直运动幅度。
- 当前次与其他有效次数的轨迹叠加；只允许平移到共同起点，不按每次幅度单独缩放，以免掩盖幅度差异。
- 可见侧肩、肘、腕关键点与二维肘角随时间的变化；无法确认同一侧或可见性不足时不输出角度。
- 展示当前组的重量、单位、记录次数和已有 RPE/RIR。复盘不推算或自动填写用力程度。

文案采用可核对描述，例如「第 5 次推起比第 1 次多用 0.4 秒」。比较须有两次有效结果，不生成统一的“标准轨迹”或“越直越好”的评价。

## 5. 指标与有效性规则

- **时间基准**：使用视频帧的实际呈现时间戳计算；不通过帧序号除以固定帧率推算，兼容可变帧率。逐帧播放使用解码帧，分析抽样率与播放帧率分开。
- **轨迹坐标**：保存校正视频旋转后的图像坐标、帧宽高、时间戳、质量状态。量化分析使用保持宽高比的图像空间；显示归一化不改变角度计算。
- **下降时间**：完整一次从顶部开始下降到进入底部区间的时长。
- **底部停顿**：底部区间内持续近似静止的时间；可识别的连续转向记为 0，遮挡或时间分辨率不足记为未知。不是触胸或比赛停顿的判定。
- **推起时间**：离开底部区间到本次顶部结束的时长。顶部是轨迹分段边界，不宣称检测到解剖学锁肘。
- **相对幅度**：本次有效轨迹的垂直跨度除以同组全部完整有效次数的垂直跨度中位数，显示百分比。无有效基准或基准接近零则显示不可计算；仅一次时不显示组内比较。
- **轨迹差异**：首版用叠加回放展示，不输出缺少验证的综合偏离分数。
- **肘角**：同一侧肩—肘—腕在图像空间构成的夹角，明确为二维投影参考；不判定肩胛收紧、两侧对称、肘外展或胸部接触。
- **质量传播**：用于某项指标的区间一旦存在未修正追踪缺口，该指标显示不可计算；其他连续有效次数仍可展示。绝不把未知显示为 0。
- **平滑与分段**：原始观察值和分析后的轨迹分别保存。平滑不跨追踪缺口，不填造观测点；分段阈值由版本化参数控制，通过真实视频校验后才纳入发布。

上述百分比是同一固定机位、同一片段内的比较，不用于跨视频推断绝对厘米位移或米/秒杠速。人体模型的三维估计也不充当尺度标定。

## 6. 技术结构

沿用仓库的 features / state / domain / data 分工，不将推理循环塞入现有训练页。

| 单元 | 职责 | 输入与输出 |
| --- | --- | --- |
| Flutter 复盘界面与控制器 | 导入、裁剪、标记、任务状态、回放与修正 | 组 ID、用户操作 → 分析请求与展示状态 |
| Android 视频服务 | 读取媒体、旋转校正、时间戳解码、取消和资源释放 | 私有视频路径、时间范围 → 有时间戳的帧 |
| 杠铃追踪器 | 从用户选择区域跟踪杠铃片中心，检测丢失 | 帧、初始区域、校正点 → 位置序列和有效性 |
| 姿态识别器 | 输出人体关键点和可见性 | 帧 → 关键点序列，可独立失败 |
| 纯 Dart 分析逻辑 | 分次、节奏、相对幅度、角度及修正后的重算 | 带时间戳的观察值、边界 → 指标与质量状态 |
| 复盘存储 | 组关联、视频与结果文件管理、版本和清理 | 复盘项目 → 元数据及私有文件 |

Android 原生层承担解码和视觉推理，通过平台通道传递进度、结果文件引用及错误；不逐帧把完整图像复制到 Dart。Flutter 负责播放器叠加和交互，耗时分析不占用 UI 线程。

姿态识别首先验证 MediaPipe Pose Landmarker Lite，模型随安装包提供，安装后离线可用；记录模型版本、来源与许可证。若卧推遮挡条件下 Lite 无法满足骨架辅助要求，再评估 Full；不得把文档性能当作真机结果。

杠铃追踪首先验证用户区域初始化的局部特征光流跟踪，并结合区域一致性和前后向误差拒绝不可靠输出。用户重定位从该时间点建立新段，不以最近人体点或背景点代替丢失目标。首版不训练专用杠铃检测器。追踪方案必须通过实际卧推视频评估后才能固定为发布实现。

## 7. 数据与生命周期

- 现有原子组实体为 `set_entry`，使用其 ID 关联；不是关联动作目录 ID 或组的显示序号。
- 新增复盘元数据表，唯一约束为每个组一项；通过新增迁移扩展当前 schema v8，不修改已经发布的迁移。
- 元数据包含项目 ID、组 ID、视频及结果相对路径、源视频尺寸/旋转/时长、裁剪范围、状态、算法与模型版本、创建和修改时间。
- 帧级轨迹、关键点、分次、人工校正和质量状态写入版本化结果文件，不将大量帧写进训练记录行。原始观察值保留，便于重算和核对。
- 视频、临时文件与结果文件只存应用私有目录；视频不上传。媒体目录不参与系统云备份，保持首版本地保存承诺。
- 保存采用临时文件完成后切换元数据引用。替换或重算失败保留旧结果；无旧结果的失败项目可重试或删除。
- 任务状态包括准备、分析、待修正、已完成、失败、已取消。取消后不留下正在分析状态；应用重启发现中断任务时显示可重试，不伪装完成。
- 删除复盘只删除应用内副本及分析，不删除相册原视频，不改训练组。删除组或整场训练时清除关联元数据，并将私有文件加入可重试清理队列；只清理受管理目录中的文件。
- 修改组重量、次数或 RPE 后，复盘显示最新训练记录，视觉结果不自动改变。再次分析记录算法版本，旧结果在新结果成功前继续可用。

### 7.1 备份边界

首版现有 JSON 备份只覆盖训练数据，不包含复盘视频、帧数据或复盘元数据。备份导出与恢复预览中明确说明这一点，不把本机路径写入可迁移备份。

整库恢复成功后清除被替换训练关联的复盘元数据，并清理其私有文件；恢复取消或事务失败时保留原复盘。恢复预览明确告知本机复盘将被清除。schema 升级须同步检查备份格式中的 schema 标识和旧版兼容校验，不直接假设当前 v6 备份代码可原样接受新库。

## 8. 失败与资源处理

- 取消文件选择：返回组记录，不创建空项目。
- 不支持的编码、损坏视频、没有视频轨道或裁剪范围无有效帧：显示具体原因并允许重选。
- 空间不足或复制中断：清理未完成副本，保留已有项目。
- 杠铃出画、遮挡、背景误跟踪：切断不可靠轨迹并提示重新定位；修正后重算该段。
- 姿态模型不可用或关键点缺失：保留杠铃复盘，说明骨架不可用。
- 相机移动或缩放：引导用户裁剪固定片段或重新选择视频，不宣称首版自动消除了机位变化。
- 后台资源被回收：恢复到可重试状态。首版不承诺持续后台推理。
- 视频或结果文件丢失：训练记录仍可使用，复盘显示文件缺失并提供删除或重新导入。
- 按流解码且只保留有限帧缓存，处理分辨率与原视频播放分辨率分离；取消、失败和离开页面时释放解码器与模型资源。

## 9. 验收与实施顺序

先验证真实视觉能力，再完成持久化和界面集成。没有真实卧推视频与目标 Android 设备的验证，不宣称该模块准确或已完成真机验收。

### 9.1 视觉可行性验证

- 使用具备使用权限的固定侧面卧推视频，覆盖清晰无遮挡、杠铃片遮挡肩肘、底部停顿、后几次明显变慢、出杠/回架、追踪短暂丢失、旋转元数据与可变帧率。
- 人工标注关键帧的杠铃片中心和完整次数边界；记录跟踪位置误差、错误跟随背景的次数、分次误差、时间边界偏差、需人工修正次数、处理时长和峰值内存。
- 发布门槛：清晰固定侧面样本的完整次数与人工结果一致；有效轨迹的人工抽检位置误差中位数不超过可见近侧杠铃片直径的 5%；时间边界偏差不超过 0.2 秒或两倍分析采样间隔中的较大值。这些是待验证的工程目标，不是已经实现的准确率承诺。
- 遮挡样本允许缺失，但人工判定为错误跟踪的片段不得作为有效结果静默输出；能通过重定位和边界修正恢复有效片段。失败样本保留并记录，不从报告中移除。

### 9.2 自动验证

- 纯逻辑：用明确时间戳的轨迹验证分次、停顿、非恒定帧率、缺口传播、原始次数不被改写、相对幅度基准、二维角度和人工边界校验。
- 存储：旧库升级、每组唯一关联、替换失败保留旧文件、取消清理、组删除、恢复成功清理、恢复失败保留、重启后任务状态与结果加载。
- 交互：视频选区和叠加坐标、逐次跳转、分次修正、缺失结果文案以及 Android/Web 能力区分。
- 对受影响的训练记录、历史编辑、删除和备份流程执行回归；无关功能不做重复扩展测试。

### 9.3 Android 实际验收

- 从已完成组导入真实视频，离线完成追踪与骨架推理、回放、修正、保存和重启查看。
- 验证慢放、逐帧和轨迹时间同步；旋转或带黑边时选择点不偏移。
- 验证取消、后台中断、重新分析、视频替换和删除；保留原相册视频与其他组数据。
- 记录目标手机上的耗时、内存与交互响应，不在实测前承诺分析速度。
- 沿用仓库当前主应用更新约定，不另建验收应用；构建成功与模型资源打包成功不替代上述验收。
