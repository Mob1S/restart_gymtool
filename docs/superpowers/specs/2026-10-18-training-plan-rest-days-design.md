# 训练计划休息日设计

日期：2026-10-18（Asia/Shanghai）。基线：`01b2687`，数据库 schema 6、备份 v4。

状态：用户已确认自然日结束，以及“完成当天提示明天休息，第二天显示今天休息”；本完整设计待审阅。尚未实施业务代码。

## 1. 已确认的行为

- 一个计划的有序周期可以包含训练日和休息日，数量、名称及顺序可自由配置。
- 休息日按设备本地自然日推进，不需要点击完成，不创建训练 session 或组记录。
- 休息从上一训练完成日期的次日开始。完成当天显示“今日已完成”，并提示“明天休息”；次日显示“今天休息”。
- 连续两个休息日占据接下来的两个自然日，之后推荐下一训练日。
- 尚未完成的训练日持续等待完成，不因时间经过自动跳过。
- 自由训练、手动补记和 CSV 导入不推进计划；每套计划独立计算进度。

例如周期为“推 → 拉 → 休息 → 腿 → 休息”：

| 实际日期与动作 | 首页状态 |
| --- | --- |
| 周二完成“拉” | 今日已完成；明天休息 |
| 周三 | 今天休息；下一次：腿 |
| 周四 | 开始训练；本次：腿 |
| 周四没有训练，周五再打开 | 仍推荐腿 |

完成日期以整场训练结束时间为准。跨午夜完成的训练从结束日期的次日安排休息。

## 2. 方案比较与选择

1. **采用：根据实际完成记录和日期推导。** 沿用每套计划最近一次有效完成作为进度来源，仅为没有完成记录的计划保存首次启用日期。适配已有轮换逻辑，删除历史后可重新推导。
2. 单独持久化当前步骤和每日推进事件。适合以后提供手动跳过／暂停，但现在需要同步历史删除、计划编辑和时钟变化，复杂度较高。
3. 固定周几安排训练／休息。适合周课表，但不能直接表达用户任意长度的分化循环，本轮不采用。

## 3. 周期推导的边界

### 3.1 有实际完成记录

按现有规则取该计划最近结束的 live／legacy 训练，使用 finished_at 和 rowid 决定先后。只有整场结束才作为来源。

- 下一项是训练日：沿用当前立即推荐下一训练日的行为，不额外添加每日一次的限制。
- 下一项是休息日：完成日剩余时间显示“今日已完成，明天休息”。第一个休息日对应完成日期加一天，之后每个休息项占一天。
- 休息段经过后停在下一训练日，直到实际完成。离开应用数天再回来，也不能越过这个未完成训练日。
- 周期最后的休息段可以跨到第一项；连续休息同样可以跨周期边界。
- 如果编辑后整个周期都变成休息项且仍有可用完成记录，则完成当天显示“今日已完成”，从次日起以该完成项的下一项为起点按日循环休息；不查找不存在的训练项。

### 3.2 没有可用完成记录

首次在首页启用该计划时，在事务中保存一次 activated_on 本地日期；只是查看管理列表或编辑草稿不启用计划。重新选择该计划不重置此日期。

- 第一项是训练日：立即推荐它，直到完成。
- 第一项是休息日：启用当天显示“今天休息”，之后按自然日经过前导休息段，再停在首个训练日。
- 只有休息日的计划允许保存，以启用日为起点按日循环，首页显示“今天休息”，可自由训练。
- 空父计划继续作为待配置状态保存，首页引导配置周期。

### 3.3 切换、手选和编辑

- 切换计划不暂停另一套计划已经开始的休息日期。
- “选择训练日”只提供训练类型的项目；选择本身不写入完成进度。休息当天也可明确手选训练日，完成后从实际完成项继续推导。
- 休息当天的“自由训练”不改变该计划的休息安排。
- 更名或排序保留既有项目 ID；从最新完成项目在新顺序中的位置继续推导。
- 最近完成项目已被删除时，回到该计划首次启用日期与当前首项的规则，不保留失效下标。
- 删除某次训练后按剩余完成记录重新推导。删除计划保留训练内容和名称快照，清理其启用信息。
- 修改计划不会改变正在进行的训练。既有 session 允许继续关联后来被改成休息类型的项目；开训事务只允许当前为训练类型的项目。

## 4. 计划编辑与首页

### 4.1 编辑计划

- 现有周期列表增加并列入口“添加训练日”和“添加休息日”。
- 列表标题改为“周期 · N 天”，摘要区分训练天数和休息天数。
- 休息项显示休息图标、名称和“休息日”，可以更名、编辑、排序、删除，支持连续休息项。
- 休息项不显示动作编辑入口。编辑弹层允许选择训练／休息类型。
- 从训练切换为休息且已有动作时，明确确认清除该项目动作清单；取消保留原草稿。只在整个计划保存成功时写库，不影响已记录训练。
- 从休息改成训练时创建空动作清单，沿用当前空动作训练日语义。

### 4.2 首页

| 状态 | 居中的主区域 | 次级操作与计划卡片 |
| --- | --- | --- |
| 推荐训练日 | 开始训练 | 当前计划、训练日及动作摘要 |
| 当天完成且次日进入休息 | 今日已完成 | 明天休息；可自由训练或手选训练日 |
| 正处于休息日 | 今天休息 | 休息项名称、下一训练日；提供自由训练 |
| 有进行中的训练 | 继续训练 | 计划卡片仍可说明今天休息，继续操作优先 |

“今天休息”和“今日已完成”是居中状态展示，不是需要点击完成的按钮。休息状态不出现空训练动作提示。仅休息计划不显示不存在的下一训练日。

保留当前按实测高度居中与小屏滚动逻辑。历史、统计与月历完成标记只使用实际训练记录。

## 5. 日期与刷新

- 采用已有 LocalDate，以本地日期的年月日计算相隔天数，不用累计24小时秒数。
- 最新训练的完成日期从 finished_at 按当前设备时区求得，与历史展示采用同一时区；改变设备时区后按当前时区重算，不回写训练历史。
- activated_on 保存为严格校验的 YYYY-MM-DD 日期。设备日期早于该日期时，按尚未经过休息日处理，不生成反向推进事件。
- 应用在后台经过午夜，回到前台立即重算；保持首页打开跨午夜时，在下一次本地午夜刷新。
- 训练已经开始后跨日不重建该 session，继续训练入口保持可用。
- 开训令牌包含当前日期、计划内容和推荐结果；午夜或编辑后提交旧推荐须重新核对，不能从休息项创建训练。

## 6. 数据与兼容

- schema 升到7：split_template 增加 kind（training／rest，默认 training）；training_plan 增加 nullable activated_on。
- 所有旧项目迁移为 training，空动作项目也不推断成休息日。旧记录和动作出现项 ID 保留。
- 激活只在首次需要时写入，旧计划默认 activated_on 为空。已有完成记录优先，不以迁移当天重置既有训练进度。
- rest 项的动作清单必须为空，仓储与备份校验均检查。训练改成休息的动作清理和类型保存使用同一事务。
- 新备份升到 v5／schema7，包含 kind 和 activatedOn；继续支持 v1–v4 恢复，升级时补 training／null，保留原单位读数、偏好、快照和历史。
- 备份引用校验不因当前项目改成休息类型而拒绝合法历史 session；开训类型限制由开训事务执行。
- 沿用当前容量检查、冲突令牌和事务回滚。首次启用并发写入采用只填空值，不覆盖既有启用日期。
- 不存休息完成记录或全局下一项下标；仅为无完成记录的推导保留必要的首次启用日期。

## 7. 实施边界与验收

本轮补休息类型、自然日推导、编辑入口、首页状态、兼容迁移和备份。未来固定周课表、通知、暂停／跳过管理不在本轮范围。

至少覆盖：

1. 训练完成当日、次日休息、休息结束、连续休息、周期末尾休息及跨月／跨年。
2. 未训练不跳日、离开多日只经过休息段、前导休息、仅休息计划及空父计划。
3. 午夜前后台刷新、跨午夜结束训练、时区或日期变化和旧开训令牌。
4. 每套计划独立、自由训练／补记／CSV不推进、手选训练和继续活动训练。
5. 项目排序、更名、删除、类型转换、取消草稿、删除最近训练后重算。
6. schema6→7和旧v1–v4备份升级，v5真实文件往返，孤立引用／非法kind／非法日期／休息项带动作拒绝及回滚。
7. 首页“今日已完成／明天休息／今天休息”文字、居中和小屏可达；旧训练记录、原始单位和统计回归。

实施前自查：已明确休息从次日起算、首次启用的例外、连续休息、未完成训练的停留、活动训练优先和历史兼容；没有未决占位项。本设计经用户审阅后再编写实施计划。
