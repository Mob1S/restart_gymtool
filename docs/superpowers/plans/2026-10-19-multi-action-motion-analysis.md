# 多动作与多机位分析实施计划

对应设计：`docs/superpowers/specs/2026-10-19-multi-action-motion-analysis-design.md`。

## 现状与约束

现有 schema 10 的 `motion_project` 只有一个顶层媒体引用，控制器和 Web/Android 桥接均以侧面卧推的手动杠铃标记为主。工作区已有未提交的前一阶段实现，本计划在原有文件上增量修改。设计中的准确率、质量提示与设备验收需要授权标注素材，软件检查不能替代这些证据。

## 实施步骤

1. 建立稳定动作 ID、版本化档案和动作/机位能力矩阵，独立定义四个基础动作的周期、轨迹目标与候选观察；未验证能力保持实验或不可评估状态。用领域测试检查配置和旧卧推默认值。
2. 在动作分析内增加目录搜索、器械/部位/类别筛选与详情页。首页保留媒体快捷入口；会话支持从目录预选动作，也支持先选媒体再确认动作与机位。
3. 将项目载荷升级为多片段结构，保留原有顶层字段读取。控制器可追加片段、切换片段及独立保存结果。清理器收集全部片段的媒体和结果引用，防止误删。
4. 扩展姿态时间序列的单片段分析接口：卧推保留现有杠铃路径；其余动作只输出证据充分的候选次数与关键点轨迹。没有验证的质量观察输出不可评估及缺失原因，避免把姿态点当器械检测。
5. 实现多角度汇总：每段保留机位与来源；只有具备可靠对应关系时展示跨角度次数对照，否则分角度列示。冲突可见，轨迹不跨坐标系叠加。
6. 运行领域、仓储、路由和状态测试以及 Flutter 静态检查；按可用环境构建 Web/Android，记录真实视频和真机验证缺口。
